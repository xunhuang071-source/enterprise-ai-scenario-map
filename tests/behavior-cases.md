# 行为回归任务

逐项执行并保留实际输出，再按验收要点人工审查。不能只写“遵守规则”。语义回归不证明真实客户项目效果。

| ID | 输入任务 | 输出必须体现 |
|---|---|---|
| B01 | 仅知道一家制造企业名称，没有其他事实；做机会规划片段，允许模拟访谈 | 画像缺口、趋势候选、标识模拟、未来模式、三期、用例及验证；不编企业事实 |
| B03 | 小企业只有4个可靠用例，用户要快速地图 | 不凑30个或5环节；主场景加轻副表，KPI不缺 |
| B04 | 同一合同审核能力从小样本验证到岗位接入再稳定运营 | 同一ID跨三期增量，不复制成三条；状态不是批次 |
| B05 | 分别设计局部缺陷识别、合同审核岗位模块、订单履约业务流 | 助手／数字员工／智能体按局部、岗位、业务流区分，同名贯穿 |
| B06 | 场景没有现成基线，预算和责任未确认 | KPI定义、样本、对照取数、阈值假设、测试与失败；不编数字和责任 |
| B07 | 价值5、可行性4、数据未知，数据授权未确认 | 待评估，不把未知当低分；先验证，无立即上线承诺 |
| B08 | 客户最新反馈将某用例改名并保留红字，旧评审稿建议回到旧名 | 最新版保留手改、稳定ID、模式—用例—计划—图级联，不能恢复旧名 |
| B09 | 模拟财务、业务、IT访谈发现两个互相矛盾的需求 | 真正输出模拟问答、矛盾与新用例，再给验证／客户确认，不冒充真人意见 |

## 流程骨架行为回归（v2.1.0）

这些是需实际检查的语义案例，不以规则文本存在当作通过证据；结构/CLI断言见test_process_backbone.py，人工/Agent样例审阅另留项目记录。

- B11 仅公司名：先画像和假设骨架，不声称行业模板就是客户现状，不直接批量吐AI清单。
- B12 客户确认流程：复用客户术语和结构，行业框架用于裁剪深化；客户手改不被新JSON覆盖。
- B13 电商三模式/混合模式：商家结算限平台、服务计费限代运营；混合模式逐过程确认，不一刀切全企业。
- B14 未来流程：能表现任务、授权、人机交接和反馈的改变，不只是节点加智能；人工复核不凑成AI用例。
- B15 行业来源与企业ID：企业挂接使用项目稳定ID；ECOM/APQC/SCOR来源独立，框架引用不证明客户痛点或确认。
- B16 SCOR范围：75条不等于75流程；七概念不是完整子过程树；RS.1.1无公式就留缺项。
- B17 工程：工程无专版需说明，不冒称RIBA/PM²已入库；行业数据集不覆盖客户专业职责时如实说明，不冒称专版。
- B18 库缺失/迁移：查询不依赖Downloads、旧工作目录或SQLite；SCOR缺失明确报告，不伪装完整。
- B19 业务与验证：纯规则可明确无需AI；基线未知设计取样，不捏造效果；同一用例跨期同ID。
