# 正式行动规划交付

使用同一大场景—三期目标态—原子用例底稿。客户确认后的内容是正式任务基线；趋势、模拟和同行提出的候选先确认，不直接当已批准任务。

## 形成成稿

1. 核对客户最新版、业务框架和确认清单，生成场景到大场景／目标态／正文／计划的映射。
2. 按客户体例组织背景、总体目标、基础与问题、共性底座、主场景与副表、实施机制和保障。
3. 大场景体现未来模式与三期状态，原子用例保持能力名称及测试卡；正式段落可汇总表达但不能删掉确认内容。
4. 计划明确三期能力递进、依赖、里程碑、业务 KPI／测试准入。年份与主责以确认记录为准，建议项显式标待确认。
5. 模式蓝图和推进矩阵从同一底稿派生；任务名、范围、时期、建设方式与正文一致。
6. 三轮评审、三层互查和确认覆盖检查后交付。

## 表达与接口

报告条目和章节不是新的盘点层级。动宾式写法嵌入统一名称，不另造一套标题。
共性底座按用例需求设置，专业用例调用共性能力；同一建设任务不能在多专业各建一遍。
保障写责任、协同、数据与权限、运营、人才、投入和评估机制，不空喊提升水平。
公文统稿、Word／Excel 排版和 PPT 表达分别交接对应技能；不将排版要求反推为内容删减。

## 验收

确认场景不增不减；每个目标／模式有用例支撑，每组用例有计划落点，每项计划有场景来源；KPI 和测试设计可执行；未确认信息不代填；客户手工改动保留；正文变化同步图表。
