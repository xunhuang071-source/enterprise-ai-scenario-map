# 场景地图交付

报告是场景底稿的表达视图，不预设品牌、联系人或销售章节。快速、完整、专题只调整深度，不强制场景数、业务环节数或重点数。

## 建议结构

1. 执行摘要：企业判断、未来业务机会、主场景、为什么优先和建议验证动作。先结论，指标有依据才写，不用承诺式收益和无来源竞争对手数字。
2. 企业画像与业务诊断：定位、客户、业务框架、现有基础、真实问题／待验证假设；行业共性不自动写成企业问题。
3. 行业实践与启示：选择相关、有依据的案例，说明可借鉴机制与本企业适用条件，不凑案例数。
4. 主场景：每个大场景写未来模式、现状和问题、三期目标态、各期关键用例、KPI／测试卡、评分依据及前置条件。
5. 路径与下一步：先做什么 Demo，如何取得基线，何时复测，哪些决定需确认；阶段是状态变化，不是工具采购批次。
6. 副表：其余场景／用例及方向，证据与待核验问题索引。可引用主场景 ID，不重复计数。

封面只带项目确认的客户、标题、日期和编制信息，未提供则留空或询问，不带移植技能的公司和联系方式。

## 主场景卡

名称／业务边界；当前状态和问题；未来模式；近期、中期、远期分别达到的状态；支撑用例 ID 与统一名称；人机分工；核心 KPI 与测试卡；优先级及依赖。
原子用例卡沿核心字段契约，不能仅用“智能化提升效率”代替机制。对外版简洁，细节在同一工作底稿关联。
统计区分大场景与原子用例；轻量任务也接受少量可靠场景，不为达到页面数扩写。
交付前按核心评审逐项检查：覆盖、命名、三期支撑、KPI、证据状态、图文一致和候选标识。
