# 合成示例：合同审核用例的两轮迭代

所有业务背景、合同和阈值均为构造演示，不是客户事实或实际产品收益。脚本使用规则替身，不冒称运行了真实 LLM。

## 场景

大场景“人机协同合同履约模式”：近期验证单任务与基准，中期覆盖例外并接入岗位，远期形成反馈和稳定回归。
同一个 U01“合同审核数字员工”贯穿三期，组织单元是合同审核岗位。轻量条款解释可用助手，跨合同履约流程的协调可用智能体，但本例不为凑载体而拆三种产品。

原子用例输入合同和规则，输出带证据的风险清单，业务人员复核决定。大场景 KPI 是人审后总耗时，用例 KPI 是关键风险召回率；两者不能互相替代。

## 测试

运行 `python3 tests/demo_iteration.py --output /会话/demo-result.json`。
32 份合成合同，16 份开发、16 份留出；正常和风险各半，固定 ID 和固定划分，金标准独立存于样本，不随预测器改变。
开发与留出都报告 TP／FP／FN／TN、精确率和召回率。作者构造的留出只示范协议，不是独立生产盲测。

- 轮 1：替身只识别“付款期限”，多种账期表达漏检。
- 改进：增加同义表达覆盖，记录版本和变更依据。
- 轮 2：同一评测协议复测，另外报告留出；不只改数字而不保存逐样本结果。
- 阈值 0.9 是合成试验假设；达标只说明替身测试流程通过，不能批准自动审核或证明真实 LLM 的泛化。
