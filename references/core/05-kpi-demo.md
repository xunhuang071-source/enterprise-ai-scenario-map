# KPI、测试基准与 Demo 迭代

## 每个场景都设计验证

大场景有业务 KPI 和各期状态，原子用例有可执行测试；样本和真实结果可以暂缺，验证设计不能空。
KPI 是业务或质量指标，不是无解释的“效率提升”。写明定义、单位、样本范围、现行对照、目标／阈值、采集方法和责任角色。

### 最小测试卡

| 字段 | 要回答的问题 |
|---|---|
| KPI 与定义 | 测什么，分子分母或计时起止是什么 |
| 样本 | 哪类任务，规模、版本、难例／例外如何覆盖 |
| 对照／基线 | 人工或现有系统如何做；未知时如何抽样测得 |
| 阈值 | 何时算可行、合格或值得继续；是确认值还是试验假设 |
| 方法 | 谁标注与复核，如何避免泄漏，对照条件是否一致 |
| 失败和护栏 | 哪些错误不允许，何时必须人审或停止 |
| 实测与改进 | 本轮结果、问题类别、改进措施、下一轮怎么复测 |

量化值有四种性质：核验实绩、测量基线、待验证目标、未知。分清性质再写入表，不把目标当已发生效果。
没有基线时可先用明确的试验假设启动小样本 Demo，并定义补测方法；只写“待校准”不足以完成测试卡。

## 两类结果一起看

1. **技术是否成立**：准确／召回、输出可用率、关键事实错误、人工接管、时延、调用成本等，按任务选择。
2. **业务是否值得**：人审后总耗时、返工、漏检、交付质量、岗位负担、实际使用率等。
不能用离线准确率代替业务价值，不能只算生成时间而漏掉审核返工。人工活跃工时与端到端历时分别定义：等待仅计入历时，不冒充人工工作时间；两项不能混称“总工时”。计时明确起止及包含环节。
分类指标名称与分母一致：召回率 = TP/(TP+FN)，精确率 = TP/(TP+FP)，假阳性率／FPR = FP/(FP+TN)，误报占提示比例／FDR = FP/(TP+FP)。不得把 FDR 标成 FPR；分母为零写不适用，并记录计算粒度是合同、条款还是风险点。
敏感任务增加授权、安全、误判等硬护栏；总分高不能抵消护栏失败。

## 迭代步骤

1. 定义目标、版本化测试集、指标、对照和阈值。
2. 开发最小 Demo，并记录数据、模型／规则、提示和业务流程版本。
3. 同口径运行并保留逐样本结果，人工复核关键结果。
4. 判断问题出在数据、边界、能力还是人机流程，决定改进项。
5. 用同一基准回归；若为测试集调参，另设留出集／新增盲测，防止只记住答案。
6. 对照业务 KPI 决定继续、扩大验证、转为人工辅助、暂缓或停止。
阶段目标随证据更新，经客户确认再进入正式扩围。

## 演示样例

[合成演示](../examples/worked-example.md) 展示两轮测试。合成输入和测试替身只说明流程与计算，不证明真实 LLM 质量或生产收益。
实际项目必须重做真实样本、数据授权和业务复核；不同模型版本和测试集的结果不能直接作提升对比。
历史同行实绩可带出处引用，不直接变成客户收益承诺。客户未来效果以测试目标表达，指标集中放 KPI／测试表，正文简述业务变化。

## 流程目标与AI测试贯通

从企业流程骨架的业务目标出发，说明AI目标流程改善什么，再对应大场景业务KPI和原子用例技术/作业测试。流程绩效不是模型准确率，离线准确率也不等于经营收益。
内置APQC指标有原定义/公式时先核对业务对象和计量口径；SCOR介绍册只有名称和编号时保留缺项，不补造公式、基准或客户目标。完整调用与来源规则见[流程骨架](08-process-backbone.md)。客户基线、阈值与收益仍通过获准样本、同任务人工作业对照、复核及返工测量。
