# 应用场景确认表模板（Markdown 规格）

「应用场景确认表」用于各部门逐项确认场景归属、规划期与建设方式。本文件是模板的完整规格：按本规格可在 Excel 或 WPS 中 5 分钟自制母版；也可用 `scripts/prepare_workbook.py` 对已有母版做年度参数化（见文末）。

模板不预置任何客户信息与年份。

## 工作簿结构

共 3 张工作表：

1. **01-编制说明**：规划目的、方法、填写规则与字段口径（内容见下）
2. **02-业务框架**：5 列，表头为 应用方向、业务分类、分类逻辑、业务、业务范围简述
3. **03-应用场景确认清单**：12 列，表头为 序号、应用方向、业务分类、业务、业务环节、人工智能应用场景名称、人工智能应用场景内容、场景出处、场景落地方式、责任部门、计划完成年度、备注说明

## 01-编制说明 内容

### 一、工作背景

**规划目的**：结合本企业业务目标、现有基础和未来趋势，形成大场景、近中远期目标态、支撑用例与验证路径。规划年度以本项目确认范围为准。

**规划方法**：双入口融合。从职责、已有应用和痛点自下而上盘点；从企业画像、趋势和战略目标自上而下推导未来模式。按实际业务框架形成大场景，先定远期终态，再倒推中期和近期状态，配置原子用例。每个场景设计 KPI 和测试基准，以 Demo、测试、改进、复测持续评估。优先级采用 AI 化价值 40%、实现可行性 30%、数据就绪度 30%，与依赖和实际排期分别判断。

**表格确认和填写说明**：各专业确认业务分类、范围和环节；对场景增删、修改、合并、拆分提出意见；完善统一名称、输入、AI 动作、产出、人机交接、来源、方式、责任和年度。空环节填「暂无场景」，不凑数量。配套工作底稿记录三期目标态、KPI 和测试基准；未确认字段留空或标待确认。

### 编制说明附图一：双入口融合导引（原图为示意页，文字转写）

标题：双入口融合——大场景、三期目标态与原子用例。从现状材料或未来模式切入，汇入同一结构；规划期按项目确认。五步：

1. **识业务**：材料入口看职责、已有应用、业务痛点；模式入口看企业画像、趋势、战略目标。
2. **定场景**：按实际业务组织大场景。描述未来业务模式，不平铺工具清单。
3. **定目标态**：先定义远期终态，再倒推中期和近期。三期是业务状态，不是三批采购。
4. **拆用例**：每期目标由原子用例支撑。助手对应局部辅助，数字员工对应岗位任务，智能体对应业务流。
5. **测与迭代**：定义 KPI、样本、对照和阈值。Demo → 测试 → 改进 → 复测。评分、依赖与排期分开。

附注：同一用例可跨期演进；主场景深写、副表轻写；没有实测值，也要写清如何验证。

### 编制说明附图二：用例设计与测试导引（原图为示意页，文字转写）

标题：用例设计与测试——让能力可感知、可验证、可迭代。名称写出业务任务和交付能力，业务人员确认内容与责任，测试支撑 Demo 持续改进。六个要点：

1. **业务任务与使用人**：谁用、做什么、结果交给谁。
2. **输入与 AI 动作**：用什么数据，模型识别、预测、生成或分析什么。
3. **载体与人机交接**：助手 / 数字员工 / 智能体；人审、授权与异常如何处理。
4. **输出与业务 KPI**：交付什么，指标如何定义、计算和测量。
5. **测试基准与阈值**：样本、人工或系统对照、目标性质、失败条件。
6. **Demo 与下一轮**：保留实测结果，判断价值和可行性，再改进复测。

合成示例（合同审核数字员工）：岗位任务是初审合同并提示风险；输入是合同与客户确认规则；AI 动作是定位例外条款并给出处；人机交接是业务人员复核和决定；KPI 是关键风险召回、人审后总耗时；测试用版本化样本与人工对照；阈值先提出假设、再实测校准；未知基线用抽样计时与复核取得。

附注：模拟访谈明确标识；真实现状、未来目标、客户确认与测试结果分别记录。

## 03-应用场景确认清单 字段口径

| 字段 | 字段说明 |
|------|----------|
| 人工智能应用场景名称 | 业务对象或任务＋智能动作＋能力载体。助手用于局部辅助；数字员工围绕岗位任务或岗位；智能体围绕业务流。统一核心名称贯穿清单、正文、计划和图。 |
| 人工智能应用场景内容 | 针对什么业务任务，基于什么输入，AI 做什么，输出交给谁，人员如何复核、决策或接管；与配套 KPI 和测试卡关联。 |
| 场景出处 | 按实际依据填写：总部或省公司部署、本地已有应用、本地规划、调研提出、同行实践、趋势推演等；记录来源定位，候选或模拟不冒充客户确认。 |
| 场景落地方式 | 应用：采用上级或既有统建能力。建设：本地建设或认领建设任务。具体方式以客户确认记录为准，未知留空。 |
| 责任部门 | 填写该场景建设或应用的牵头责任部门；多部门协同的填牵头部门。 |
| 计划完成年度 | 近期、中期、远期对应年度待项目确认；排序不自动等于完成年度。未明确时留空或选择「待确认」。 |
| 备注说明 | 补充意见、待确认事项或测试卡索引；未知不代填，原手工标记保留。 |

## 下拉规则（Excel 自制时配置）

- **场景落地方式列（I 列，I2:I1000）**：列表下拉，选项为「应用,建设」。
- **计划完成年度列（K 列，K2:K1000）**：列表下拉，选项为「已完成,待确认,近期年,中期年,远期年」，三个年度按项目实际规划期替换（如 2029年,2030年,2031年）。

## 生成项目副本

已有 Excel 母版时，不要直接改母版。用脚本生成项目副本，只改年度相关字段，其余版式逐字节保留：

```bash
python3 scripts/prepare_workbook.py --template 你的母版.xlsx --output 项目确认表.xlsx --years 2029 2030 2031
```

- 三个年度必须不同且递增；脚本拒绝覆盖已存在的输出文件。
- 生成后复核客户口径、年度与下拉选项，再发给部门确认。
- 本仓库不附带二进制母版；按上方规格自制即可，或联系序创信获取（见仓库 README 联系方式）。
