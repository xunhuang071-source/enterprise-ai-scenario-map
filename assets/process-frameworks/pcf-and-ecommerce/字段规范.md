# 数据字段规范 · v1.1.0

兼容原11个APQC数据集的v1.0.0字段；新增本地参考数据集的来源性质、编制信息与适用条件。原APQC底稿未因此改写。

本包的数据底稿为UTF-8 JSON/JSONL。JSONL一行一个完整对象；字段名使用英文，内容保留原文。空缺用`null`，不填“无”或猜测值。编号按字符串保存，避免浮点数改写层级。

## 1. catalog.json

- `schema_version`：字段规范版本。
- `created_at`：本次转换时间，带时区。
- `datasets`：各数据集的身份、年份、版本、状态、目录、节点数、指标记录数和行业别名。
- `known_missing`：已知本批资料中没有的数据集。

年份是文件整理标签；正式解释以metadata中的证据为准。catalog及行业目录来自同一份规范化元信息。

## 2. metadata.json

| 字段 | 含义 |
|---|---|
| dataset_id | 英文行业标识、版本、年份、语言组成的数据集身份 |
| industry_zh / industry_en | 行业名称 |
| version | 当前框架版本，不是作为底版的跨行业框架版本 |
| language | 原始主名称语言：en或zh |
| file_year | 中文文件名使用的年份 |
| date_type | release / generated / copyright / same_version_reference / compiled / unspecified；compiled为本地编制时间 |
| year_basis | 原始日期证据；同版PDF作为依据时明确记录 |
| source_file | 相对数据包根目录的原Excel路径 |
| source_sha256 | 原Excel的SHA-256 |
| compared_to_version | 原文件已有差异对照所使用的旧版本；不代表拥有旧版完整内容 |
| status | ready可查询；needs-review有阻塞异常；failed读取失败 |
| statistics | 计数、层级、定义、双语、重复、指标等信息 |
| issues / blocking_issues | 原始资料差异和阻塞异常，二者分开 |
| supporting_text | 原说明页、摘要、版权、文本框、页脚等附属信息 |
| attribution_text | 从附属信息中识别出的版权/许可相关文字及位置 |
| compatibility_resolution | 适用时记录旧XLS读取方式和已绕开的解析器兼容问题 |

`ready`仅表示转换结果可用，并不替原始资料宣称内部完全一致。原有整理备注可能保留早期读取失败记录；当前处理结果以status、reader及compatibility_resolution为准。

## 3. processes.jsonl

### 身份与结构

- `dataset_id`：所属数据集。
- `node_id`：`dataset_id:hierarchy_id`，数据集内按层级位置唯一。
- `pcf_id`：APQC流程概念编号。同一编号可跨行业出现；电信原表中也存在同一数据集不同层级复用的情况，因此不作为全局唯一键。非APQC本地参考保持null，不用本地参考号填入该字段。
- `hierarchy_id`：规范化层级编号。旧版顶层`1`规范化为`1.0`，其原始写法保留在`hierarchy_original`。
- `level`：实际深度；`1.0`为第1级，`1.1`为第2级，以此类推。
- `parent_id`：父节点的node_id；顶层为null。编号`1.1`的父级为`1.0`，不是一个虚构的`1`节点。

分类树不表示执行顺序。排序按编号各段的整数值，避免10.0排到2.0前面。

### 原文与定义

- `name_original`、`language`：主表原始名称和语言；仅去除首尾空白，保留内部表达。
- `name_en`、`name_zh`：原文件有明确对照时填入，无来源时null。
- `description`、`description_source`：原定义及工作表、行号、字段位置。优先保留Combined的Element Description；同文件Glossary terms可补充空缺。不同定义不强行覆盖。
- `metrics_available`：原表Y/N映射为true/false；未提供则null。与本包实际指标记录数量分别解释。
- `difference_index`、`change_details`、`compared_to_version`：原始版本对照字段，不重新推导。
- `source_sheet`、`source_row`：主节点所在Excel工作表及**从1开始**的行号。
- `field_sources`：中英文对照、词表等补充来源。
- `legacy_origin`：旧版的Source列，含底版或行业定制提示。
- `source_cell_text`、`source_column`：旧版保留名称、编号和括号ID未拆分前的文字，以及原Excel列号。

没有定义的旧版节点保持空缺。不跨数据集借用定义，也不将V7.0.5中文名称未经核对地映射到V8.0。

## 4. metrics.jsonl

一行一条原表指标关联记录，不按metric_id全局去重。同一指标可以关联多个流程。

单文件超过分发体积限制时按行序拆分为`metrics.jsonl`与`metrics.part2.jsonl`，索引按文件名排序顺序读取，记录格式与总数不变。

- `metric_record_id`：数据集加原指标表行号，唯一。
- `dataset_id`、`node_id`、`pcf_id`、`hierarchy_id`：流程关联。
- `process_name`：指标表所写流程名称，保留原文，即使与主流程名称存在细微差异。
- `metric_category`、`metric_id`、`metric_name`：指标类别、ID和名称。
- `formula`、`units`：原公式和单位，仅作为资料保存，不执行。
- `source_sheet`、`source_row`：原指标表位置。

当前10,041条均可关联流程。指标表完全空白的行被排除，排除计数保留在metadata.statistics。

## 5. supplement.jsonl

保存不宜静默丢弃、也不直接覆盖主节点的内容，当前包括：

- `section_field_conflict`：章节与Combined字段不同；含两种原值与章节出处。
- `category_conflict`：Categories与Combined字段不同；保留类别页原记录。
- `unmatched_glossary`：未关联主流程的词表条目，当前为原表Root根节点说明。
- 其他异常类型由转换器原样记录；不应因其没有标准流程节点而丢弃。

查询`get`通过`source_variants`返回该节点相关补充项；默认摘要提供`source_variant_count`提示。无节点关联的说明仍在supplement中保留。

## 6. SQLite索引与查询输出

- SQLite不是唯一资料源，可由catalog、metadata、processes、metrics、supplement和检索别名重新构建。
- `nodes`中保留与JSONL相同的原记录；FTS5用于英文全文检索，配合中文/英文子串与辅助词匹配。
- 行业与版本先筛选，关键词作OR召回，名称命中优先；这不是向量语义匹配，不保证业务语义排序完美。
- 数据库只读方式用于正常查询；SQL参数化绑定，不把用户文本当作SQL或FTS运算符直接拼接执行。
- 每个结果含行业、版本、年份、编号、父级路径与原表出处。
- `get`返回一个节点的完整原记录、定义及来源差异。metrics的公式需`--full`显式展开。
- `total`是当前条件下的总结果数，`returned`是实际本页条数，`next_offset`是下一页起点；可因字符预算而少于请求条数。
- `max-chars`用于限制整个JSON响应。无法在预算内放入单条完整记录时，返回提示，不把截断的定义冒充完整原文。

## 7. 授权、可重建和更新

原资料授权与归属文字见各数据集metadata和根目录[授权与归属](授权与归属.md)。重新发布底稿、查询结果或衍生材料时应保留适用声明。

转换器禁止默认覆盖已有数据；纯Excel资料包的显式`--retry`要求原输入哈希不变。含本地参考的混合包禁止Excel全量`--retry`覆盖目录。源资料更新后，创建新的输出目录并校验，不用复用旧底稿混补。

## 8. 本地编制电商参考扩展

- `framework_family=domestic_ecommerce_reference`、`source_type=analyst_compiled_reference`、`is_official=false`：不是APQC原始框架或官方行业标准。
- `compiled_version=0.1`和`compiled_at`属于本地版本与编制时间，不能套给五份来源原文。`complete_catalog=false`、`client_validated=false`不声明行业完备或客户已验证。
- `reference_id`使用ECOM前缀，作本地引用；查询仍以`hierarchy_id`定位。APQC编号跨行业对照不包含这些节点。
- `name_original`在本数据集中表示编制后标准名称，不是外部文献逐字名称；`description_origin=analyst_synthesis`明确说明规范化定义的编制属性。
- `source_references`逐节点保存来源ID、URL、原文章节/PDF物理页及支持范围；原文标题、作者、机构、日期和限制集中在sources.json。
- `source_explicit`表示原文明确涉及过程主题；`multi_source_synthesis`表示多源综合；`analyst_extension`表示基于来源的进一步分析展开。三者都不把本地规范化名称、角色及输入输出冒充源作者原句。
- 所有三级参考活动均标为analyst_extension。它们是操作级参考，不是从原文直接导出的统一作业规范。
- `applicable_business_models`：self_operated自营/品牌零售、marketplace第三方平台、agency代运营；`applicability_notes`说明合同及责任条件。适用标签不等于必选或自行执行。
- `roles`、`inputs`、`outputs`、`related_systems`是编制参考。系统示例不是要求客户必须自建或采购的软件。
- 没有Excel来源时，source_sheet与source_row为null；source.file定位本地编制基线，source_references定位外部资料。没有原始指标库时不生成metrics.jsonl。
- 三级拆解、角色和输入输出需结合客户实际流程确认；不将节点层级当强制执行顺序。

### 检索中的性质提示

list、search、get等结果显示framework_family、source_type和is_official。原APQC元数据没有这些新字段时，查询工具按既有APQC资料身份显示默认值，不重写其底稿。这里is_official=true表示由该框架发布机构提供的原始资料，不表示APQC是政府标准或法律要求。

SQLite额外的search_context只索引本地参考号、模式条件、角色、输入输出和系统示例；它是可重建检索字段，不修改JSONL原记录。业务词可命中名称、定义或上下文，命中上下文不代表过程一定由该经营模式自行执行。
